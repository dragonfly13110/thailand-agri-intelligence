# ร่าง Data Contract: สถิติทะเบียนเกษตรกรสำหรับ Thailand Core

สถานะ: **ร่างสำหรับเจ้าของโครงการและ DOAE ทบทวน ยังไม่ได้ส่งหรือรับรอง** ไม่มีการเชื่อมฐานข้อมูลทะเบียนรายบุคคลจากร่างนี้

## ขอบเขตที่ขอ

ขอเฉพาะสถิติรวมตามพื้นที่ที่ DOAE อนุญาต เช่น จำนวนครัวเรือน พื้นที่ขึ้นทะเบียน และกิจกรรมการเกษตร รายจังหวัด/อำเภอ/ตำบลตามระดับที่เผยแพร่ได้ โดยคงสินค้า หน่วย ฤดู ปีเพาะปลูก และรอบปรับปรุงจริง ไม่ขอชื่อบุคคล เลขประจำตัว รหัสทะเบียนรายบุคคล เบอร์โทร ที่อยู่ พิกัดแปลง หรือข้อมูลสมาชิกครัวเรือน

เจ้าของข้อมูลกำหนดระดับพื้นที่และเกณฑ์ปกปิดกลุ่มขนาดเล็ก หากต้องระงับค่าให้ส่ง null พร้อมเหตุผล ห้ามแทนด้วยศูนย์ และไม่อนุมานค่าที่ถูกปกปิดจากยอดรวม

## โครงสร้างส่งมอบที่ต้องตกลง

| Field | ความหมายและเงื่อนไข |
|---|---|
| dataset_id / resource_id | รหัสชุดและทรัพยากรที่ใช้เชื่อมหลักฐานสิทธิ์ |
| revision_id / supersedes_revision_id | รุ่นข้อมูลและรุ่นที่ถูกแทน เก็บรุ่นเก่าได้ตามข้อตกลง |
| metric_code / metric_definition | นิยามตัวชี้วัด เช่น ครัวเรือนที่ไม่ซ้ำภายในขอบเขตใด |
| commodity_code / classification_version | รหัสสินค้าและรุ่นพจนานุกรม ไม่รวมสินค้า/พันธุ์โดยชื่อคล้ายกัน |
| spatial_support / admin_level | ระดับพื้นที่จริงที่ได้รับอนุญาต |
| province_code / district_code / subdistrict_code | รหัสข้อความที่คงศูนย์นำหน้า ส่งเฉพาะระดับที่มีจริง |
| boundary_version / valid_from / valid_to | รุ่นพื้นที่และช่วงที่รหัสมีผล เพื่อแก้รหัสยกเลิก/แบ่งเขตโดยมีหลักฐาน |
| period_type / period_start / period_end | ความถี่และขอบเขตเวลาตามนิยามเจ้าของข้อมูล |
| crop_year / season / planting_round | ปีเพาะปลูก ฤดู รอบปลูก แยกจากปีปฏิทินเมื่อไม่ตรงกัน |
| value / unit | ตัวเลข nullable และหน่วยที่ยืนยัน ค่าว่างกับศูนย์มีความหมายต่างกัน |
| record_role / aggregation_rule | detail/subtotal/total และวิธีรวมที่อนุญาต ห้ามรวม household ซ้ำข้ามกิจกรรม |
| completeness_status / missing_reason | พื้นที่/รอบที่ครบ บางส่วน ไม่เผยแพร่ ถูกปกปิด หรือดึงไม่สำเร็จ |
| issue_at / release_at | วันออกรายงานและวันเผยแพร่ของ revision นี้ หากไม่ทราบคง null |
| source_updated_at / retrieved_at | วันแก้ต้นทางและวันรับข้อมูล แยกจาก release_at |
| source_url / payload_sha256 | หลักฐานต้นทางและ checksum ของชุดที่ส่งมอบ |
| license_status / exact_terms_url | เงื่อนไขใช้ภายใน/เผยแพร่/ส่งต่อ และสัญญาอนุญาตฉบับที่ครอบคลุม resource นี้ |

## วิธีรับและตรวจ

1. เจ้าของข้อมูลยืนยันนิยาม ตัวอย่าง schema และสิทธิ์ระดับ resource ก่อนรับรอบใช้งานจริง
2. เลือกช่องทางองค์กรที่ได้รับอนุมัติ ไม่ใช้ Git public หรืออีเมลส่งข้อมูลส่วนบุคคล และไม่ใส่ credential ในไฟล์/manifest
3. ส่งแบบ snapshot รายรอบพร้อม manifest จำนวนแถว checksum และเวลาตัดยอด หรือ delta ที่มี revision ordering ชัดเจน
4. ผู้รับตรวจ schema, missing, key ซ้ำ, subtotal, หน่วย และรหัสพื้นที่ตามรุ่น เก็บ raw/quarantine และผลตรวจโดยไม่แก้ต้นทาง
5. ตัวชี้วัดพร้อมใช้เมื่อฝ่ายเจ้าของข้อมูลยืนยันวิธีรวม/coverage และผู้รับตรวจผลกับยอดต้นทางที่มีนิยามเดียวกันแล้ว
6. ระบุช่องทางรายงานการแก้ไข ข้อมูลถูกถอน การเปลี่ยน schema การหยุดส่งข้อมูล และผู้รับผิดชอบให้ตรวจสอบย้อนกลับได้

## เรื่องที่ยังต้องตกลง

- นิยามครัวเรือนซ้ำข้ามแปลง/สินค้า/โครงการ และขอบเขตของยอดรวม
- ความถี่จริง เวลาเผยแพร่ย้อนหลัง และสิทธิ์เก็บ historical revisions
- เกณฑ์ปกปิดข้อมูลในพื้นที่ขนาดเล็กและข้อห้ามคำนวณย้อนกลับ
- สิทธิ์ใช้ภายใน สิทธิ์เผยแพร่ตารางอนุพันธ์ การให้เครดิต และระยะเวลาเก็บรักษา
- เงื่อนไขการรับรองตัวเลขและการระบุผู้มีสิทธิ์ใช้ข้อมูลในรายงาน

การเข้าถึงหน้า catalog สาธารณะหรือดาวน์โหลดไฟล์ได้ไม่ถือเป็นการอนุมัติ Data Contract นี้ ผู้รับผิดชอบของทั้งสองฝ่ายต้องยืนยันก่อนใช้ช่องทางที่ต้องมีสิทธิ์
