วันที่ตรวจ: 31 ตุลาคม 2026

### ขอบเขตของแคตตาล็อก

คำค้น “เกษตร” พบ 5,752 รายการในพอร์ทัล แต่ส่วนใหญ่เป็นสำเนาของ 77 จังหวัดและรายการซ้ำ งานนี้จึงเก็บเฉพาะชุดจากหน่วยงานส่วนกลาง/ชุดที่เกี่ยวข้องจริง และตัดสำเนาจังหวัดออกเพื่อไม่ให้ตัวเลขซ้ำ

คำค้นที่ผลเยอะมากถูกตัดที่ 3 หน้า (300 รายการ) ได้แก่ ข้าว, เนื้อที่เพาะปลูก, ดิน, ชลประทาน, แหล่งน้ำ, GAP, น้ำท่วม, ภัยแล้ง, ปศุสัตว์, ประมง, ป่าไม้, ปลา, ไฟป่า, สัตว์น้ำ, กลุ่มเกษตรกร

ดังนั้น 326 resource นี้คือ **รายการที่คัดและทดสอบแล้ว** ไม่ใช่ทั้งหมดของพอร์ทัล; ถ้าต้องการไล่ทุกหน้า/ทุกสำเนา สามารถขยายเพิ่มได้

## 3. วิธีเชื่อม Power BI

### 3.1 API JSON (แนะนำ)

ทุก resource ที่มี `api_url` ในแคตตาล็อกใช้รูปแบบเดียวกัน:

```
https://data.go.th/api/3/action/datastore_search?resource_id=<RESOURCE_ID>&limit=5000&offset=0&sort=_id
```

ขั้นตอน:

1. Power BI → Get Data → Web
2. วาง URL ด้านบน (แทน `<RESOURCE_ID>` จากไฟล์ CSV)
3. เลือก JSON → Expand `result` → Expand `records`
4. ตั้งชนิดข้อมูลของคอลัมน์ตัวเลข/วันที่เอง เพราะ API ส่งตัวเลขหลายคอลัมน์มาเป็นข้อความ
5. ทำซ้ำหน้าโดยเพิ่ม `offset` ทีละ 5,000 จนกว่าจะได้ครบ `result.total`

ตัวอย่าง Power Query (M) สำหรับดึงทุกหน้า:

```m
(ResourceId as text) =>
let
    Url = "https://data.go.th/api/3/action/datastore_search",
    Limit = 5000,
    GetPage = (offset as number) =>
        Json.Document(
            Web.Contents(
                Url,
                [Query = [
                    resource_id = ResourceId,
                    limit = Text.From(Limit),
                    offset = Text.From(offset),
                    sort = "_id"
                ]]
            )
        )[result],
    Pages = List.Generate(
        () => [o = 0, r = GetPage(0)],
        each List.Count([r][records]) > 0,
        each [o = [o] + Limit, r = GetPage([o] + Limit)],
        each [r][records]
    ),
    Rows = List.Combine(Pages)
in
    Rows
```

ข้อจำกัดที่ทดสอบแล้ว:

| สิ่งที่ทดสอบ | ผล |
|---|---|
| `limit` สูงสุดที่ลอง | 5,000 แถว/ครั้ง ใช้ได้ |
| `offset` | ใช้ได้ |
| `sort` | ใช้ได้ (เช่น `_id desc`) |
| `filters` | ใช้ได้ (ทดสอบกรองปีแล้ว total ลดลงจริง) |
| SQL (`datastore_search_sql`) | **ไม่มี** — ตอบ 400 |
| API key | data.go.th ไม่ต้องใช้ key |
| opend.data.go.th | ต้องใส่ header `api-key`; ไม่ใส่ได้ 401 |

หมายเหตุ: API เคยตอบ 502 เป็นครั้งคราว ให้ใส่ retry 2 ครั้งและเว้นจังหวะ ไม่ควรตั้ง refresh ถี่เกินไป

### 3.2 ไฟล์ CSV / XLSX

ใช้คอลัมน์ `file_url` ในแคตตาล็อก:

- CSV: Get Data → Web (หรือ Text/CSV) แล้ววาง `file_url`
- XLSX: ดาวน์โหลดไฟล์แล้วใช้ Excel connector
- ไฟล์บางชุดอยู่บนเว็บของหน่วยงาน (เช่น `catalog.oae.go.th`, `dld.gdcatalog.go.th`) ไม่ได้อยู่บน data.go.th โดยตรง ถ้าเปิดใน Power BI Service ไม่ได้ ให้ดาวน์โหลดหรือใช้ API แทน

### 3.3 JSON ที่ไม่ใช่ datastore

มี 37 ชุดที่เป็น REST JSON ของหน่วยงานโดยตรง เช่น

- `apiwarning.acfs.go.th` — ข้อมูลซ้อนใน `data.items`
- `dataservice.cad.go.th` — ตอบเป็น array
- `agriapi.nabc.go.th` — มี `page=` แบ่งหน้า

ชุดเหล่านี้ต้องเขียนการแปลงเฉพาะ ไม่สามารถใช้ M template ด้านบนได้ตรง ๆ

มี 11 ชุดที่ URL มี API key ฝังอยู่ (GISTDA/TMD) ไฟล์ส่งมอบปิดค่า key แล้วและทำเครื่องหมาย `needs_api_key = true`; ต้องขอ key จากหน่วยงานก่อนใช้ URL เหล่านั้น รายละเอียดรายชุด: [embedded-api-keys-report.md](embedded-api-keys-report.md)

## 5. คุณภาพข้อมูลและข้อควรระวัง

### ปัญหาโครงสร้างที่พบ

- **หัวตารางสลับแกน 3 ชุด** — ข้อมูลการผลิตข้าว/พืชไร่ ปี 2562, ข้อมูลการผลิตไม้ผล/ไม้ยืนต้น ปี 2562, พื้นที่ป่าไม้รายจังหวัด ปี 2558 ใช้ตรง ๆ ไม่ได้ ต้องแก้ต้นทางหรือแปลงใหม่

- **ไม่ใช่ตาราง 25 ชุด** — PDF, HTML, ZIP, XML (TMD API ใช้ demo key), WFS ของ RID, หน้า Power BI embed ของหน่วยงานอื่น

### เรื่องความหมายของตัวเลข

- มีทั้งระดับ **ประเทศ / ภาค / จังหวัด / ตำบล / แปลง / ประเทศคู่ค้า** — ห้ามบวกข้ามระดับ เช่น อย่าเอาจังหวัดรวมกับยอดประเทศ
- หลายชุดมี `attribute` หรือ `item` บอกว่าแถวนั้นคือ “เนื้อที่เพาะปลูก”, “ผลผลิต”, “ผลผลิตต่อไร่” หรือ “ราคา” — ต้องแยกก่อนวัด
- หน่วยอยู่ในคอลัมน์ `unit` และบางครั้งอยู่ในชื่อคอลัมน์ — ห้ามรวมข้ามหน่วย (ไร่/ตัน/บาท/ร้อยละ)
- ตัวเลขส่วนใหญ่เป็นข้อความ, มีช่องว่างท้าย, มีคำว่า `None`, มี `-` แทนค่าว่าง — ต้องทำความสะอาด
- ปีเป็น พ.ศ. (เช่น 2566) ไม่ใช่ ค.ศ. — ต้องแปลงก่อนใช้กับ date table
- จำนวนแถวไม่เท่ากับ coverage: บางชุดมี 12 แถวแต่ครอบคลุมทั้งประเทศ บางชุดมี 300,000 แถวแต่เป็น GIS ระดับแปลง

### รหัสที่ต้องมีตาราง lookup

- `breed_id` ของข้อมูลพืชอายุยาว ยังไม่มีตารางแปลงเป็นชื่อพืชในชุดนี้
- `tradeflow` ของข้อมูลประมง ต้องยืนยันว่าเลขใดคือ import/export
- `PRODUCT_TYPE` ของข้อมูลมาตรฐานสินค้าเกษตร เป็นรหัสตัวเลข
- `tambon_id` เป็นรหัส 6 หลัก ใช้ 2 หลักแรกเป็นรหัสจังหวัดได้ แต่ควรมีตารางจังหวัด/ตำบลมาตรฐาน

## 6. โครงสร้างโมเดลที่แนะนำ

โมเดลจากชุดที่คัดแล้วมี 10 ตารางข้อเท็จจริง (fact) และ dims กลาง:

| Fact ที่แนะนำ | ชุดต้นทาง | Grain | Refresh |
|---|---|---|---|
| `FactDailyPrice` | S1 NABC รายวัน | วันที่ × สินค้า × ตลาด × จังหวัด | รายวัน |
| `FactWeeklyPrice` | S2 NABC รายสัปดาห์ | ปี/สัปดาห์ × สินค้า (ประเทศ) | รายสัปดาห์ |
| `FactMonthlyPrice` | S3 + A18 + B6 | เดือน × สินค้า × พื้นที่ | รายเดือน |
| `FactCropProduction` | A1–A12, A20–A21 | ปี/เดือน × จังหวัด × พืช × ตัวชี้วัด × หน่วย | รายปี/รายเดือน |
| `FactLivestock` | A13–A16 | ปี × จังหวัด × ประเภทสัตว์ | รายปี |
| `FactFeedTrade` | A17 | เดือน × ประเภทอาหาร × ประเทศ | รายเดือน |
| `FactFisheryTrade` | S6 | เดือน × HS × ประเทศ × tradeflow | รายเดือน |
| `FactExport` | S7 | เดือน × HS × ประเทศ × ท่า × FORM | รายเดือน |
| `FactWaterDaily` | S4/S5 | วันที่ × เขื่อน/แหล่งน้ำ | รายวัน |
| `FactCoop` | B1 CAD | ปีงบประมาณ × ประเภทสหกรณ์ × ตัวชี้วัด | รายปี |

Dimensions ที่ควรทำ:

- `DimDate` — ปี พ.ศ./ค.ศ., เดือน, ไตรมาส, สัปดาห์
- `DimProvince` — 77 จังหวัด + รหัส
- `DimProduct` — ชื่อพืช/commodity/subcommodity/HS
- `DimMarket` — ตลาด/แหล่งราคา (NABC มี 44 ตลาด)
- `DimCountry` — ประเทศคู่ค้า
- `DimDam` — เขื่อน/แหล่งน้ำ + ขนาด + จังหวัด
- `DimStandard` — มาตรฐาน/ใบรับรอง
- `DimPort` — ท่า/ด่านศุลกากร

หลักการ:

1. ห้ามรวม S1/S2/S3 ใน fact เดียว เพราะ grain ต่างกัน (ตลาด/จังหวัด vs ประเทศ)
2. ทุก fact ควรมีคอลัมน์ `Source` และ `Unit` เพื่อไม่ให้รวมข้อมูลต่างชุดโดยไม่รู้ตัว
3. ความสัมพันธ์เป็น single direction จาก fact ไป dim
4. ห้าม sum ค่าที่หน่วยต่างกันหรือ grain ต่างกันใน measure เดียว; ห้ามบวก A3 (ร้อยละ) กับปริมาณ
5. เก็บ missing เป็น null อย่าเติม 0
6. ตั้ง incremental refresh เฉพาะ fact ที่มีวันที่จริง (S1, S4, S5, S6, S7)

## 7. งานที่ควรทำต่อ

1. เลือก 8–10 fact จาก S/A ที่ตรงกับคำถามหลักของรายงาน (แนะนำเริ่ม S1, S4, S5, S6, S7 + A2, A11, A17)
2. ทำ Power Query template: S1/S4/S5 ใช้ parameter วันที่วนย้อนหลัง; S6/S7 ใช้ folder combine
3. ทดสอบ refresh 1 รอบกับข้อมูลจริง แล้วเทียบจำนวนแถว/ช่วงปีกับ best-apis.csv
4. ตรวจสิทธิ์ของชุดที่เลือก โดยเฉพาะ OAE “อื่นๆ” (12 ชุด), NABC บางสินค้า NC, A5 NC, RID/CAD ที่ไม่มี metadata
5. สร้าง star schema ตามข้อ 6 แล้วทำ dashboard
6. ก่อนเผยแพร่ภายนอก ให้เจ้าของงานอนุมัติราย resource และเก็บหลักฐานสิทธิ์
7. ถ้าต้องการ ผมทำไฟล์ `.xlsx` สำหรับเปิดดูแคตตาล็อก หรือโครง Power BI (PBIP/Power Query) ต่อได้
8. ถ้าจะใช้ข้อมูลสดจาก API ที่มี key ให้ทำตาม [env-apis-powerbi.md](env-apis-powerbi.md): เริ่ม 5 แหล่งที่ไม่ใช้ key ก่อน แล้วค่อยทำ proxy สำหรับ GISTDA/TMD/Meteostat
