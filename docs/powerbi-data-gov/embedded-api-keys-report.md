# รายงาน: 11 ชุดข้อมูลที่มี API key ฝังอยู่ใน URL

ตรวจเมื่อ 31 ตุลาคม 2569 (2026-10-31) จากแคตตาล็อก `docs/powerbi-data-gov/` ที่ทดสอบ data.go.th จำนวน 321 ชุด / 326 ไฟล์

**สถานะ:** ค่า key ถูกปิดเป็น `<REDACTED>` ในไฟล์ส่งมอบทุกไฟล์แล้ว รายงานนี้ไม่แสดงค่า key ต่อมามีการทดสอบซ้ำตามคำขอของเจ้าของงาน โดยไม่บันทึกค่า key และผลคือ key ไม่สามารถใช้ได้ (รายละเอียดในหัวข้อผลทดสอบซ้ำ)

## สรุปสั้น

- จาก 326 ไฟล์ มี **11 ไฟล์** ที่ URL ของแหล่งข้อมูลมีค่า key ฝังมาใน metadata สาธารณะของ data.go.th
- แยกเป็น **GISTDA 7 ไฟล์** (พื้นที่ปลูกพืช 6 ชนิด + ความชื้นในดิน) และ **กรมอุตุนิยมวิทยา (TMD) 4 ไฟล์** (อากาศเกษตร/สถานี/อากาศผิวพื้น/อุทกวิทยา)
- ปัญหาไม่ได้อยู่ที่ API ของ data.go.th (ตัว CKAN ไม่ต้องใช้ key) แต่อยู่ที่ **URL ของ API หน่วยงานที่ฝัง key แล้วถูกนำมาเผยแพร่ต่อ**
- key ที่พบ **ไม่ใช่สิทธิ์ของเรา** ห้ามนำไปใช้ต่อ ต้องขอ key ของหน่วยงานเอง
- ทดสอบก่อนลบค่า key: GISTDA ตอบ **403** ทุกไฟล์; ทดสอบซ้ำภายหลังพบว่าเป็น `REFERER_REQUIRED` / `REFERER_NOT_ALLOWED` (key ถูกล็อกกับ referer ที่ไม่ใช่ของเรา); TMD ตอบ **200** แต่เนื้อหาคือ `Authentication fail`; OpenD ตอบ **401**
- ทั้ง 11 ไฟล์ติดป้าย `Open Data Common` แต่ไม่มีลิงก์/เวอร์ชันสัญญา และ data.go.th ตั้ง `isopen=false` จึงยังไม่ผ่านเกณฑ์เผยแพร่ของโปรเจกต์

## API key คืออะไร (อธิบายแบบง่าย)

API key คือรหัสผ่านสำหรับเรียกข้อมูลจาก API ของหน่วยงาน ใครถือ key ก็เรียกในนามบัญชีนั้นได้ (ภายในโควตาที่กำหนด)

ถ้า key ถูกฝังใน URL แล้ว URL นั้นถูกเผยแพร่ ก็เท่ากับเอารหัสผ่านไปแปะไว้ในที่สาธารณะ ทุกคนที่เปิด metadata ของชุดข้อมูลนั้นเห็นได้

## พบได้อย่างไร

1. ดึงข้อมูลคำอธิบายชุดข้อมูล (metadata) ของทั้ง 321 ชุดผ่าน API ของ data.go.th
2. ตรวจฟิลด์ URL ของแต่ละไฟล์ (`url`, `original_url`) พบพารามิเตอร์ `api_key` และ `ukey` ฝังอยู่
3. รวมรายการที่ไม่ซ้ำกันได้ 11 resource
4. ลบค่า key ออกจากไฟล์ทุกไฟล์ก่อนส่งมอบ แล้วสแกนซ้ำ: ไม่เหลือค่า key ที่ใช้งานได้ (0 จุด)

การทดสอบลิงก์ API ครั้งแรกทำก่อนลบค่า key เพื่อดูว่าแหล่งข้อมูลยังใช้งานได้หรือไม่ ต่อมามีการทดสอบซ้ำตามคำขอของเจ้าของงาน โดยไม่บันทึกค่า key (ดูหัวข้อผลทดสอบซ้ำ)

## ความเสี่ยง 5 ข้อ

1. **สิทธิ์ไม่ใช่ของเรา** — key ที่พบอาจเป็นของบัญชีตัวอย่างหรือบัญชีที่ถูกยกเลิกแล้ว การนำไปใช้ต่ออาจผิดเงื่อนไขการใช้บริการ
2. **key รั่วไหล** — URL อยู่ในแคตตาล็อกสาธารณะ ใครก็เห็น ถ้านำ URL ไปใส่ในรายงาน Power BI แล้วแชร์ไฟล์ key จะติดไปด้วย
3. **รายงานพังโดยไม่รู้ตัว** — หน่วยงานอาจเปลี่ยนหรือยกเลิก key เมื่อไรก็ได้ (GISTDA 403 อยู่แล้ว) รายงานจะ refresh ไม่ได้
4. **สิทธิ์เผยแพร่ข้อมูลยังไม่ชัด** — ทั้ง 11 ชุดติดป้าย Open Data Common แต่ไม่มีลิงก์/เวอร์ชันสัญญา และ `isopen=false` จึงยังไม่ควรเผยแพร่ตัวเลขออกนอกทีม
5. **ข้อกฎหมาย/จริยธรรม** — การใช้ credential ที่หลุดอาจถือเป็นการเข้าถึงโดยไม่ได้รับอนุญาต ไม่ควรทดลองเดา key หรือใช้ key นี้ต่อ
