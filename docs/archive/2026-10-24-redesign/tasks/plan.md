# แผนส่งมอบศูนย์ข้อมูลเกษตรผ่านเว็บ Next.js

**ทิศทางล่าสุด 24 ต.ค. 2569:** ข้อมูลการเกษตรที่แสดงบนเว็บต้องมาจาก API หรือสคริปต์ที่ดึงจากแหล่งต้นทางตาม [ADR-002](../docs/decisions/0002-source-backed-web-data.md) หน้า workstation ที่อ่าน `data/local`/DuckDB เป็นเพียงต้นแบบและยังไม่ผ่านเกณฑ์นี้ การมี route API ครอบการอ่านไฟล์ในเครื่องไม่ถือว่าเชื่อม API ต้นทาง

สถานะ 24 ต.ค. 2569: มี Next.js catalog, workstation tables, หน้าพื้นที่/โครงการ/กรณีข้าว และ backup/restore verification อยู่แล้ว แต่ชุดข้อมูลตัวเลขยังอ่าน local staging/DuckDB และบาง request เปิด raw file; จึงเป็น prototype ไม่ผ่าน source-backed web acceptance ตาม ADR-002 ส่วน source connector DOAE CKAN สำหรับ metadata เพิ่งต่อใน /catalog และยังรอตรวจ build/browser; สิทธิ์ตัวเลขยัง pending

## เป้าหมายและลำดับอ้างอิง

มี `/projects` สำหรับอ่านหลักฐานประกาศโครงการทางการ (กิจกรรมพืชใช้น้ำน้อย DOAE), สถิติแผน-ผลรายหน่วยงาน (โครงการ PGS กรมพัฒนาที่ดิน 202 แถว) และการกระทบยอดแผน-ผลเพาะปลูกระดับประเทศ (Plan vs Actual Reconciliation: ฤดูฝน 477 vs 3 แถว และฤดูแล้ง 599 vs 10 แถว สถานะ INCOMPARABLE ไม่ทับซ้อนพื้นที่) แสดง planned province/reporting units/fiscal period กับสิ่งที่ยังยืนยันไม่ได้ โดยคง registered projects ที่ตรวจรับแล้วเป็น 0 ตามจริง

มีระบบบูรณาการหลักฐานเชิงพื้นที่รายจังหวัดใน `/areas/[provinceCode]` เชื่อมโยง 4 มิติข้อมูลจริง: 1) รายงานความเสียหายจากภัยพิบัติ DOAE P0 (น้ำท่วม/ภัยแล้ง/ขาดแคลนน้ำ), 2) แหล่งน้ำธรรมชาติและอ่างเก็บน้ำ DWR พร้อมความจุ/ปริมาตรกักเก็บ, 3) แถวเพาะปลูก รต.01/ไม้ยืนต้น/แผนฤดูแล้ง, และ 4) การจับคู่มาตรการ (Intervention Matching) สถานะ UNVERIFIED พร้อม Candidate Initiatives โครงการเตรียมการ โดยคงหลักการความปลอดภัย 5 ประการ: Zero Synthetic Composite Score, Fail-Closed Gap Inference, Native Spatial Support, Pending License Preservation, Workstation Session Gate

เพิ่ม [กรณีข้าวนครปฐม](../docs/rice-pilot.md) ที่ `/areas/73/rice`: เปิดแถวผลิตจริง เลือกราคาประเทศเอง และฝนรายเดือนของจุดกริดในปีที่เลือก พร้อม provenance/null/coverage และแยก source-year semantics แก้ engine แผน/ผลและซ่อมสอง diagnostic rows แล้ว

เว็บมี `/data` สำหรับเปิดดูรายการที่คัดไว้ 17 คำอธิบาย/6 หมวดและทางเข้าตาราง/ราคา ตรวจ browser desktop/mobile/693px ผ่านทั้งหมด และแก้ routing/links เรียบร้อย

ตรวจบัญชีล่าสุด 24 ต.ค. 2569 ใน [บัญชีข้อมูลปัจจุบัน](../docs/current-data-inventory.md) แล้ว เพิ่ม CLI แฟ้มอ้างอิงแถวพืชกับ DOPA snapshot ภายในเครื่อง มีที่มา/ค่า missing และ gates ที่ยังปิด ดูคำสั่งใน [runbook](../docs/runbook.md#แฟ้มตรวจหลักฐานพืชรายพื้นที่ในเครื่อง)

สร้างศูนย์รวมข้อมูลเกษตรทั้งประเทศให้เจ้าหน้าที่ ผู้บริหาร หน่วยงานอื่น และผู้ใช้ทั่วไปค้นข้อมูล สำรวจความสัมพันธ์ ตรวจหลักฐาน และนำข้อมูลที่ได้รับสิทธิ์ไปใช้วางโครงการและติดตามผล ผ่านหน้าเว็บภาษาไทยที่ใช้ได้ทั้งคอมพิวเตอร์และมือถือ

เป้าหมายด้านข้อมูลอยู่ที่ [ศูนย์ข้อมูลเกษตรระดับประเทศ](../docs/national-agriculture-data-center.md) การตัดสินใจด้านเทคโนโลยีอยู่ที่ [ADR-001](../docs/decisions/0001-nextjs-web-delivery.md) เมื่อเอกสารเดิมขัดกัน ให้ใช้คำสั่งเจ้าของงานล่าสุด → HANDOFF → เป้าหมายศูนย์ข้อมูลและแผนนี้ → เอกสารเฉพาะข้อมูล ส่วนสเปก Thailand First v1.4 ใช้อ้างอิงแหล่งข้อมูลและหลักคุณภาพที่ไม่ขัดกับคำสั่งล่าสุด

ยุติ Power BI ในฐานะผลิตภัณฑ์และช่องทางส่งมอบ ไม่ใช่การพักไว้รอทำภายหลัง ไม่มีงานบังคับ PBIP/PBIR, Power Query, DAX, Desktop, Service หรือ Fabric Trial ในเกณฑ์เสร็จใหม่ ไม่สร้าง BI embed ในเว็บแทนการย้ายระบบ

## สิ่งที่ใช้ต่อและขอบเขตการย้าย

| ส่วน | การดำเนินการ |
|---|---|
| Python connectors, schema, coverage, crosswalk และ lineage | ใช้ตัวดึงต้นทางเดิมต่อ; ย้ายการอ่าน/ตรวจข้อมูลออกจาก request ของเว็บ และไม่ใช้ local raw/staging/DuckDB เป็น web runtime |
| Export และสัญญาแบ่งปันข้อมูล | ใช้ API ฝั่ง server หรือคลังที่เก็บเฉพาะข้อมูล normalize แล้วและมีสิทธิ์; สัญญา `/v1/*` ยังไม่ใช่บริการ HTTP ที่ deploy แล้ว |
| สูตรคำนวณ/guard rails ที่เคยตรวจใน Python | ใช้เป็นหลักฐานประกอบ ตรวจค่าที่ API และเว็บได้รับกับต้นทางใหม่ ไม่ถือว่า DAX simulation รับรองเว็บ |
| Next.js + TypeScript + App Router | เป็นชั้นเว็บหลัก วางแอปใน `web/` เมื่อเริ่มลงมือ รุ่น package/Node และ hosting ให้ตรวจเอกสารทางการและบันทึกเมื่อสร้างแอป |
| `powerbi/`, generators, tests และ snapshots เก่า | เป็น legacy สำหรับอ้างอิง ไม่พัฒนาเพิ่ม ไม่รันเพื่อสร้าง deliverable ใหม่; ลบภายหลังเมื่อไล่ dependencies และตรวจสำเนาที่ต้องเก็บแล้ว |

ประวัติ W0 เป็นการปรับแผนอย่างเดียว รอบ W1/W2 ถัดมาสร้างเว็บและติดตั้ง packages ที่จำเป็นแล้ว ไม่เปลี่ยน schema/ข้อมูลต้นทาง ไม่ลบ raw หรือสำเนา และยังไม่ deploy

## เส้นทางข้อมูลที่เว็บจะใช้

`API/เว็บไซต์ต้นทาง → connector ฝั่ง server หรือสคริปต์ดึงข้อมูล → ตรวจ schema/สิทธิ์/grain/lineage → API หรือคลังข้อมูล normalize ฝั่ง server → Next.js → browser`

- ใช้ API ต้นทางโดยตรงเมื่อข้อมูลมีขนาด/ความถี่เหมาะสม; ใช้ connector แบบกำหนดรอบสำหรับข้อมูลย้อนหลังหรือชุดใหญ่ ไม่ดาวน์โหลด raw มาเป็นไฟล์ runtime ของเว็บ
- connector ตรวจ response ที่ไม่เชื่อถือด้วย timeout, ขนาดสูงสุด, pagination, allowlist ฟิลด์ และ schema; บันทึก source URL, retrieved_at, revision/checksum และสถานะ license
- เก็บได้เฉพาะข้อมูล normalize ที่มีสิทธิ์ตามขอบเขต; ประมวลผล raw ในหน่วยความจำ ไม่เขียนลง workstation/local checkout; กรณีกติกาต้นทางบังคับเก็บ ให้ใช้ private managed storage พร้อม retention policy
- Browser เรียก API ของเรา; Server Components และ Route Handlers ใช้ connector/API server-side ตามความเหมาะสม ไม่ส่ง credential ไป browser และไม่รับ URL/SQL อิสระจากผู้ใช้
- cache ต้องเป็นไปตามเงื่อนไขแหล่งข้อมูล ผูกกับ revision/เวลา/สิทธิ์ และแยก public จาก internal; `pending` ห้ามกลายเป็น public แม้ metadata จะมองเห็นได้
- DOAE CKAN metadata เป็น connector ชุดแรก แสดงรายการกับลิงก์ทางการเท่านั้น; resource observations ยังไม่เปิดจนกว่าสิทธิ์และ schema รายชุดผ่าน
- reader ปัจจุบันที่เปิด `data/local`, `exports/private`, staging หรือ DuckDB จาก request ต้องย้าย/ปิดก่อนผ่าน acceptance; ห้ามคัดลอกข้อมูลเหล่านี้เข้า `web/public`, bundle, build artifact, props หรือ response

## หน้าที่จะพัฒนาตามลำดับ

หน้า `/`, `/catalog`, `/catalog/[id]`, `/about`, ดาวน์โหลดบัญชี `/catalog.json` และ `/explore` แบบตารางจริงใน workstation mode สร้างแล้ว เพิ่ม `/areas` และ `/areas/[provinceCode]` สำหรับค้นแถวพืชตามชื่อจังหวัด พร้อมพืช/ปีและจำนวนค่า missing แล้ว ยังไม่ใช่ crosswalk ที่รับรอง/ยอดจังหวัด เพิ่ม `view=price_trend` ของชุด `all-farmgate-prices` เพื่อดูกราฟ/ตารางราคาแยกสินค้า คุณภาพ หน่วยและตลาด เทียบเดือนก่อน/เดือนเดียวกันปีก่อนตามปฏิทิน พร้อม lineage และ null/gap แล้ว ส่วน workflow เชื่อมหลายแหล่งและโครงการยังรอข้อมูลและการตรวจ

| หน้า | ผู้ใช้ทำอะไรได้ | ข้อกำหนดข้อมูล |
|---|---|---|
| `/` ศูนย์ข้อมูล | เห็นว่ามีข้อมูลเรื่องใด เข้าหน้าค้นหา และเห็นข้อจำกัดสำคัญ | จำนวนรายการค้นพบ แถวข้อมูลที่มี และข้อมูลพร้อมเผยแพร่ต้องแยกกัน |
| `/catalog` และ `/catalog/[id]` | ค้นหา/กรองหน่วยงาน หมวด พื้นที่ ช่วงเวลา ดูนิยาม หน่วย ที่มา revision สถานะ และสิทธิ์ | เป็นงานชุดแรก ใช้ข้อมูลจริงที่อนุญาต มี pagination และลิงก์ที่แชร์ตัวกรองได้ |
| `/areas/[provinceCode]` | เห็นข้อมูลที่ครอบคลุมพื้นที่และสิ่งที่ยังขาด พร้อมหลักฐาน | 77 จังหวัดเป็นแกนรหัส ไม่ใช่การรับรองว่ามีข้อมูลครบ ประเทศ/สถานี/กริดไม่ถูกแจกค่าลงจังหวัด |
| `/explore` | เลือกตัวชี้วัด สินค้า ช่วงเวลา ดูตาราง/กราฟและข้อค้นพบ | เริ่มหนึ่งกรณีที่ผ่านเกณฑ์ หน่วย/ฤดู/เกรด/ตลาดตรงกัน ไม่เฉลี่ยรวมราคาต่างสินค้า |
| `/projects` | ค้นโครงการ พื้นที่เป้าหมาย และแผนเทียบผล เมื่อมีหลักฐาน | ปัจจุบันโครงการที่ยืนยันได้ 0 รายการ แสดงว่ายังยืนยันไม่ได้ ไม่ตีว่าไม่มีโครงการในพื้นที่ |

ทุกหน้าต้องอ่านได้บนมือถือ ใช้คีย์บอร์ดได้ มี label ภาษาไทย ไม่ใช้สีเป็นข้อมูลเพียงอย่างเดียว และแยก loading, empty, partial, stale, needs_review, unavailable และ error พร้อมเหตุผล/เวลาข้อมูล โดยนิยามจาก contract ไม่เดาจาก HTTP 200

## งานเป็นช่วงและเกณฑ์ผ่าน

| ช่วง | ขอบเขตและ dependencies | เกณฑ์ตรวจรับ |
|---|---|---|
| W0 ปรับทิศทาง | เป้าหมาย คู่มือ สเปก และ handoff | ไม่มีงานส่งมอบ BI ในแผนปัจจุบัน; เอกสารเก่ามีป้ายประวัติชัดเจน |
| W1 connector catalog ต้นทาง | เริ่ม DOAE CKAN package metadata แบบจำกัด; ใช้ metadata เท่านั้น | มี code ต่อ source API ใน `/catalog`; ยังรอตรวจ build/browser, timeout/error และสถานะข้อมูลแปลกก่อนผ่าน |
| W2 source-backed data API | เลือก resource ที่สิทธิ์/schema ผ่าน; วาง API ฝั่ง server และเปลี่ยนหน้าเว็บจาก local readers | ไม่มี request ที่อ่าน raw/local files; API คง null, grain, revision, สิทธิ์ และเปรียบค่าที่แสดงกับต้นทาง |
| W3 พื้นที่และการสำรวจ | ต่อจาก W2 และ crosswalk/ตัวชี้วัดที่ผ่านตรวจ | เลือกจังหวัด/สินค้า/เวลาแล้วไม่รั่ว grain หรือคูณแถว; หนึ่งข้อค้นพบมีที่มา วิธีคำนวณและข้อจำกัด; ตรวจหน้าจอเทียบค่าต้นทาง |
| W4 โครงการและแผนเทียบผล | ต่อจาก W2 และทะเบียนโครงการจริง/สิทธิ์ | เมื่อพื้นที่/พืช/ฤดู/รอบ/หน่วยไม่ตรง คืน `INCOMPARABLE`; ไม่มีโครงการตรวจแล้วคงสถานะไม่ทราบ; ไม่สร้างเป้าหมายหรืองบจำลอง |
| W5 เผยแพร่และดูแล | ผ่านช่วงที่เลือกส่งมอบและสิทธิ์ของทุก payload | ตรวจ preview ด้วย browser, ทดสอบ URL ตรง/มือถือ/ข้อมูลล้มเหลว, ตรวจ artifact ไม่รั่วข้อมูลภายใน, มีรอบ refresh/backup/rollback; ตรวจ production แยกหลัง deploy |

เริ่ม W1 → W2 ได้โดยไม่รอข้อมูลทั้งประเทศครบ งานข้อมูลอากาศ v2 และการตรวจ DWR/GISTDA/HII เดินตามความจำเป็นของหน้าที่จะใช้ ไม่ใช่เงื่อนไขบังคับก่อนเว็บ catalog แต่ห้ามเปิด metric ที่ยังพักอยู่

## เกณฑ์เสร็จของผลิตภัณฑ์

เกณฑ์ต่อไปนี้เป็นงานค้าง ไม่ได้ผ่านจากการปรับเอกสาร:

- ผู้ใช้ค้นชุดข้อมูล เปิดรายละเอียดที่มา/สิทธิ์/เวลา/หน่วย และรับข้อมูลที่อนุญาตผ่านเว็บได้จริง
- มี coverage ที่อิง resource จริง และอย่างน้อยหนึ่ง workflow จากข้อมูลหลายแหล่งที่ตรวจสอบย้อนกลับได้ ไม่ใช้จำนวนจังหวัดในทะเบียนแทนความครบ
- กราฟ ตาราง API และไฟล์ดาวน์โหลดอ้าง snapshot เดียวกัน รักษา null, revision และเหตุผลเทียบไม่ได้
- สูตร/contract ผ่านการตรวจไม่ได้แปลว่าเว็บผ่าน ต้องตรวจ browser interaction, accessibility พื้นฐาน, mobile และค่าที่ render จริง
- ไม่มีข้อมูลภายใน/PII/secret ใน public HTML, JSON, props, cache, source maps หรือ artifacts; ไม่อ้างว่าใช้งานภายในปลอดภัยก่อนตรวจ authorization
- มี pipeline/refresh ที่ตรวจรอบจริง การสำรองและ restore ที่พิสูจน์แล้ว และ deployment ที่ตรวจจริง โดยไม่พึ่ง Power BI/Fabric; build ในเครื่องไม่เท่ากับ production พร้อมใช้
