# คำแนะนำสำหรับ AI ที่ทำงานใน repository นี้

1. อ่าน [HANDOFF.md](HANDOFF.md) ก่อนเริ่ม เป็นสถานะล่าสุด เช็กลิสต์ หลักฐาน พาธข้อมูล และลำดับงานต่อ จากนั้นอ่าน [แผนเว็บ Next.js](tasks/plan.md), [ADR-001](docs/decisions/0001-nextjs-web-delivery.md) และเอกสารเฉพาะส่วนที่จะเปลี่ยน สเปก Thailand First v1.4 ใช้อ้างอิงแหล่งข้อมูล/หลักคุณภาพที่ไม่ขัดกับคำสั่งล่าสุดเท่านั้น
2. คำสั่งเจ้าของงานล่าสุด 23 ต.ค. 2569: ทำศูนย์รวมข้อมูลเกษตรทั้งประเทศเป็นเว็บ Next.js ให้กรมส่งเสริมการเกษตรและหน่วยงานอื่นค้น ใช้ข้อมูลร่วมกัน วางโครงการตรงพื้นที่/ปัญหา และติดตามผล ยุติ Power BI เป็นช่องทางส่งมอบ ไม่ใช่พักไว้ทำภายหลัง ไม่เพิ่มงาน PBIP/DAX/Desktop/Service/Fabric หรือ BI embed; ใช้ Python/DuckDB เดิมต่อ เริ่มจาก catalog ที่ตรวจสิทธิ์แล้วและเว็บชุดแรก พร้อม coverage ตามจริง รหัสอ้างอิงและเกณฑ์เชื่อม อ่าน [เป้าหมายและลำดับงาน](docs/national-agriculture-data-center.md)
3. ตรวจ `git status` ก่อนแก้ เก็บงานค้างของผู้ใช้/agent อื่นไว้ ตรวจสถานะจริงและ `git log` แทนการเดาจากประวัติแชตว่า commit/push แล้วหรือยัง
4. Repository เป็น public เฉพาะโค้ดและข้อมูลที่อนุญาตเผยแพร่ `data/local/` และ `exports/private/` มีชุดสิทธิ์ pending ห้ามนำเข้า Git/public artifacts ห้ามเปลี่ยนสถานะสิทธิ์โดยไม่มีหลักฐาน
5. รักษา missing เป็น null, source grain, version/revision และพื้นที่จริง ประเทศ/สถานี/จุดกริดไม่เท่ากับจังหวัด ห้ามรวมราคา/ผลผลิตเฉลี่ยข้ามสินค้า เกรด หน่วย ฤดู หรือ subtotal
6. Tests/schema ผ่านไม่ได้แปลว่า API/browser/render/accuracy/deployment ผ่าน ให้บันทึกสิ่งที่ทดสอบจริง ตรวจค่าบนเว็บกับต้นทางและทดสอบ desktop/mobile; ผล TOM/DAX เก่าเป็นหลักฐาน legacy ไม่ใช่เกณฑ์ส่งมอบใหม่ ห้ามคัดลอก data/local หรือ exports/private เข้า web/public หรือส่งผ่าน HTML/JSON/props/cache; secret อยู่ฝั่ง server เท่านั้น
7. หลังจบงานแต่ละช่วง อัปเดต HANDOFF.md และ docs/progress.md พร้อมหลักฐาน งานค้าง และคำสั่งทำต่อ ไม่ลดเกณฑ์เสร็จจากสเปกให้เหลือเพียง prototype
