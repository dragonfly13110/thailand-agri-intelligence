# สัญญาและส่วนต่อประสานการแบ่งปันข้อมูลสำหรับหน่วยงานพันธมิตร (Data Sharing Interface & External Partner API Contracts)

**สถานะปัจจุบัน:** เป็นสัญญาและฟังก์ชันทดลองในเครื่อง ยังไม่มี API ที่เปิดให้หน่วยงานใช้จริงหรือระบบยืนยันตัวตน `license_scope` เป็นค่าที่ผู้เรียกส่งเข้ามา จึงไม่ใช่หลักฐานว่าได้รับสิทธิ์ ข้อมูลโครงการระดับรายการยังไม่มีเป้าหมายพื้นที่ที่ตรวจแล้ว และบัตรหลักฐานทุกจังหวัดคืนสถานะมาตรการ `UNVERIFIED`; `public_only` งดส่งบัตรที่ข้อมูลสิทธิ์ pending

**ช่องทางใหม่ 23 ต.ค. 2569:** สัญญา/export นี้เป็นจุดเริ่มตรวจสำหรับ [เว็บ Next.js](../tasks/plan.md) แทน BI ไม่ใช่ backend ที่พร้อมเปิดใช้ทันที เริ่ม snapshot ที่ตรวจ allowlist ฟิลด์/สิทธิ์/PII และ manifest แล้วอ่านฝั่ง server ห้ามเสิร์ฟ feed ภายในตาม `license_scope` ที่ผู้ใช้ส่งมาเอง ก่อนเปิด internal HTTP ต้องมี authentication/authorization ที่ตรวจฝั่ง server และแยก public cache; เส้นทาง `/v1/*` ด้านล่างยังเป็น contract จนมี implementation และผลตรวจจริง

**ตัวอ่านในเครื่อง:** เว็บมี `/api/local-session` และ `/api/local-data` สำหรับ fixed statistical views 8 มุมมองตาม [คู่มือเว็บ](../web/README.md) แล้ว ใช้ explicit local flag, loopback host และ session cookie ก่อนอ่าน read-only/no-store เส้นทางนี้เป็น workstation mode เท่านั้น ไม่ใช่ `/v1/*` หรือ partner API และไม่ให้สิทธิ์เผยแพร่ข้อมูล pending ระบบบัญชีผู้ใช้หลายคนยังไม่สร้าง

รันคำสั่งตรวจสอบและทดสอบ:


สัญญาข้อมูลทางการ (Data Contract): [data_contracts/data_sharing.schema.json](../data_contracts/data_sharing.schema.json)

## 2. โครงสร้างจุดเชื่อมต่อ API (Standard Endpoints)

ทุก Endpoint ส่งออกข้อมูลในรูปแบบมาตรฐานสากล พร้อมระบุ `feed_id`, `partner_agency`, `requested_at`, `payload_sha256`, และ `governance_notes`:

### 1) `/v1/catalog`
* **หน้าที่:** แสดงบัญชีชุดข้อมูล ทรัพยากร เจ้าของข้อมูล ระดับความละเอียด (Grain) และสถานะสิทธิ์
* **License Gating:** ภายใต้ scope `public_only` ข้อมูลที่มีสถานะสิทธิ์ `pending` จะถูกจำกัดการเข้าถึงเป็น `LICENSE_PENDING_AGGREGATE_METADATA_ONLY` เพื่อป้องกันการรั่วไหล

### 2) `/v1/coverage`
* **หน้าที่:** แสดงบัญชีความครอบคลุมข้อมูลทั้งประเทศที่ระดับ `source × area × period × metric`
* **ตัวกรอง:** รองรับการกรองตาม `province_code` และ `commodity`
* **ความถูกต้อง:** แจ้งเหตุผลของข้อมูลที่ขาดหาย (missing reason) ตามจริง และรักษา missing เป็น null

### 3) `/v1/spatial-evidence`
* **หน้าที่:** บัตรหลักฐานเชิงพื้นที่จากรายงาน DOAE สำหรับตรวจปัญหาที่พบ พร้อมเหตุผลว่าทำไมยังระบุสถานะมาตรการไม่ได้
* **ตัวกรอง:** กรองตาม `province_code` (เช่น `81` กระบี่, `31` บุรีรัมย์)
* **การชี้เป้า:** ระยะนี้ใช้ `UNVERIFIED` ทั้ง 77 จังหวัด ห้ามอนุมานว่าไม่มีปัญหาหรือไม่มีโครงการจากข้อมูลที่ยังไม่ครบ

### 4) `/v1/projects`
* **หน้าที่:** สัญญาสำหรับทะเบียนโครงการที่รอข้อมูลเป้าหมายระดับโครงการ; ขณะนี้คืนรายการที่ตรวจแล้ว 0 รายการ
* **ตัวกรอง:** กรองตาม `fiscal_year` (เช่น `2567`), `commodity` (เช่น `ข้าว`), และ `province_code`

## 3. สถาปัตยกรรมความปลอดภัยและการรับรองความถูกต้อง (Cryptographic Integrity & Governance)

1. **SHA-256 Payload Digest:** ทุกคำตอบของ API มีค่าแฮช `payload_sha256` ที่คำนวณจากเนื้อหาข้อมูลแบบ deterministic เพื่อให้ระบบปลายทางตรวจสอบได้ว่าข้อมูลไม่มีการแก้ไขระหว่างทาง
2. **Scheduled Feed Bundles:** ฟังก์ชัน `export_partner_feed_bundle` รองรับการส่งออกข้อมูลเป็นชุดไฟล์ JSON พร้อมไฟล์ `manifest.json` เพื่อใช้ในการแลกเปลี่ยนข้อมูลแบบ Batch/Scheduled Sync ระหว่างหน่วยงาน
3. **Data Protection & Least Privilege:** ข้อมูลแปลงและทะเบียนเกษตรกรรายบุคคลถูกคุ้มครองตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 โดยชั้นการแบ่งปันข้อมูลนี้ให้บริการเฉพาะ **สถิติรวมเชิงพื้นที่ (Aggregate Spatial Layer)** เท่านั้น
