# บันทึกการสำรวจแหล่งข้อมูลปศุสัตว์และสัตว์น้ำ (กรมปศุสัตว์ / กรมประมง)

สำรวจเมื่อ: 2026-10-25 · ผู้สำรวจ: lane บูรณาการ (web livestock dashboard)
สถานะ: metadata ยืนยันแล้ว · ตัวเลขยัง pending (ดูหัวข้อ 5 และ 6)

---

## 1. วัตถุประสงค์และขอบเขต

เพื่อหาแหล่งข้อมูลจริงสำหรับแดชบอร์ด `สถิติปศุสัตว์และสัตว์น้ำเศรษฐกิจ` (`/livestock`) โดยต่อยอดจาก
`src/tadih/livestock.py` และ `src/tadih/fisheries.py` ซึ่งเดิมดึงข้อมูลระดับประเทศเท่านั้น

โจทย์เดิมระบุ "รายภูมิภาค" — การสำรวจยืนยันว่า**มีข้อมูลรายจังหวัดที่ใช้ได้จริง** และหลายชุดมีคอลัมน์
`ภาค` มาให้เอง แต่ต้องระวังเรื่องสำคัญ 2 ข้อ (ดูหัวข้อ 4) และห้ามรวมแกนภาคของสองหน่วยงานเข้าด้วยกัน

## 2. วิธีสำรวจ (bounded)

```powershell
# ค้นหา dataset ทั้งแคตตาล็อก
Invoke-RestMethod 'https://dld.gdcatalog.go.th/api/3/action/package_search?q=*:*&rows=500'
Invoke-RestMethod 'https://catalog.fisheries.go.th/api/3/action/package_search?q=*:*&rows=500'

# ดู metadata ของ dataset
Invoke-RestMethod 'https://dld.gdcatalog.go.th/api/3/action/package_show?id=<package_id>'

# ดู schema + ตัวอย่างข้อมูล
Invoke-RestMethod 'https://catalog.fisheries.go.th/api/3/action/datastore_search?resource_id=<id>&limit=2'
```

หมายเหตุ: การค้นด้วยคำค้นภาษาไทยผ่าน `package_search?q=<ภาษาไทย>` ได้ผลลัพธ์ 0 รายการทั้งสองแคตตาล็อก
(URL encoding ของ query string ภาษาไทย) — ต้องใช้ `q=*:*` แล้วกรองในโค้ดแทน

`datastore_search_sql` ของ CKAN ใช้ไม่ได้กับ `catalog.fisheries.go.th` (ตอบ 400) จึงต้องแบ่งหน้า
(`limit`/`offset`) แล้ว aggregate ในโค้ด

## 4. ข้อค้นพบด้านความหมาย (สำคัญ — ห้ามละเลย)

### 4.1 สองหน่วยงานใช้ "ภาค" คนละระบบ — ห้ามรวม

| หน่วยงาน | ภาคในข้อมูล | จังหวัด |
|---|---|---|
| กรมปศุสัตว์ | ภาคเหนือ 17 · ภาคกลาง 26 · ภาคตะวันออกเฉียงเหนือ 20 · ภาคใต้ 14 | 77 |
| กรมประมง (กุ้ง) | ภาคตะวันออก · ภาคกลาง · ภาคตะวันออกเฉียงเหนือ · ภาคใต้ตอนบน · ภาคใต้ตอนล่างฝั่งอ่าวไทย · ภาคใต้ฝั่งอันดามัน | 35 |

- กรมปศุสัตว์**ไม่มีภาคตะวันออก** และนับจังหวัดภาคตะวันออก (จันทบุรี, ฉะเชิงเทรา, ระยอง, ตราด,
  ชลบุรี, ประจวบคีรีขันธ์, ปราจีนบุรี, สมุทรสาคร, สมุทรปราการ ฯลฯ) ไว้ใน **ภาคกลาง**
- กรมประมงแบ่งภาคใต้เป็น 3 ส่วน และไม่มีภาคเหนือ
- ดังนั้นจังหวัดเดียวกันอยู่คนละ "ภาค" ขึ้นอยู่กับหน่วยงาน — ผลรวมข้ามแหล่งจึง **ต้องไม่ทำ**
  แดชบอร์ดจึงแสดงภาคตามแหล่งของตัวเอง พร้อมป้ายกำกับฐานของภาค และใช้ crosswalk มาตรฐาน 5 ภาค
  เฉพาะกรณีที่แหล่งไม่มีคอลัมน์ `ภาค` (ชุดสัตว์น้ำจืด/ปลาน้ำกร่อย) โดยระบุว่าเป็นค่าที่ "derive" ไม่ใช่ค่าจากต้นทาง

### 4.2 กรมปศุสัตว์ไม่แยก ไก่เนื้อ / ไก่ไข่

แคตตาล็อกมีเพียง `จำนวนไก่` (รวม) — ไม่มี dataset แยกไก่เนื้อกับไก่ไข่
→ **ห้ามสร้างการแยกย่อยขึ้นเอง** ระบบแสดง "ไก่ (รวม)" พร้อมหมายเหตุช่องว่างอย่างชัดเจน

### 4.3 ป้ายชนิดสัตว์น้ำมีช่องว่างท้ายแถว

ข้อมูลดิบมีบางแถวเป็น `"ปลานิล "` (มี trailing space) → `distinct` ดิบได้ 38 ค่า แทนที่จะเป็น 20
ทุก consumer ต้อง `.trim()` ก่อนเทียบค่า

### 4.4 รุ่นปี 2569 ของกุ้งไม่มีคอลัมน์ `ปี`

resource `890c72ed-…` เปลี่ยนชื่อคอลัมน์เป็น `Attribute`/`Value` และ **ตัดคอลัมน์ `ปี` ออก**
ปีอ้างอิงจึงมาจากชื่อ resource เท่านั้น ไม่ใช่จากแต่ละแถว

### 4.5 หน่วยวัดต่างกัน — ห้ามรวม

`ปริมาณ` (ตัน) กับ `มูลค่า` (พันบาท) เป็นคนละหน่วย ห้ามบวกกัน และชุดกุ้งมีทั้ง `กุ้งขาว` กับ `กุ้งกุลาดำ`
ซึ่งเป็นคนละชนิด — ต้องแยกย่อยก่อนรวม ห้ามบวก subtotal ซ้ำ

### 4.6 จำนวนแถวรุ่นปี 2568 ของกุ้งน้อยผิดปกติ

2568 มี 280 แถว เทียบกับ 2567 ที่มี 770 แถว (ชุดจังหวัด/เดือนเดียวกัน) — ต้องสอบถามผู้ดูแล DOF
ก่อนเทียบข้ามปี

## 5. สถานะสิทธิ์และการตัดสินใจเผยแพร่

`config/resource_licenses.json` บันทึก resource พี่น้องของ DLD/DOF ไว้เป็น `pending` /
`project_publication_approved: false` โดยยังไม่คลี่คลาย 3 ข้อ:

1. ตัวแปรสัญญาอนุญาต Open Data Common รุ่นที่แน่นอน และสิทธิ์ในการเผยแพร่ซ้ำ
2. ปีอ้างอิงเป็นปีปฏิทินหรือปีงบ/ปีผลิตของหน่วยงาน
3. เวลาเผยแพร่ย้อนหลังของแต่ละรุ่น

ทรัพยากรที่ค้นพบใหม่ในรอบนี้ยังไม่เคยผ่านการตรวจสอบ จึงถือเป็น `pending` เช่นเดียวกัน

**การตัดสินใจ (ตาม AGENTS.md ข้อ 3 และ precedent ของ lane สภาพอากาศ):**

| ชั้นข้อมูล | สถานะ | การเผยแพร่ |
|---|---|---|
| metadata (ชนิดสัตว์, หน่วย, grain, ช่วงปี, จำนวนจังหวัด/แถว, URL ต้นทาง, สิทธิ์, ข้อจำกัด) | ยืนยันแล้วจากต้นทาง | **เผยแพร่ได้** |
| ตัวเลขจริงจากต้นทาง | pending | **ห้ามออก public API / HTML / props / cache** |

เว็บชั้น web จึงทำแบบ **sample mode** เหมือน lane สภาพอากาศ:

- `LIVESTOCK_SAMPLE_MODE = true` พร้อมค่าตัวเลขสังเคราะห์แบบ deterministic (seed จาก hash ของ
  `speciesId|regionId|yearBe`) — **ไม่ได้สร้างจากขนาดจริงของต้นทาง** และไม่มี `Date.now()`/`random`
  ในเส้นทางคำนวณค่า
- ทุกตัวเลขมี `sample: true`, API meta เป็น `access: 'metadata_only'` และมี `warnings` แจ้งทุกครั้ง
- UI แสดงแบนเนอร์ "ข้อมูลตัวอย่างเพื่อสาธิตหน้าจอ" ชัดเจน พร้อมส่วน "ข้อจำกัดของข้อมูล"
- เมื่อสิทธิ์ผ่าน (M4/M5) ให้ปิดสวิตช์และสลับเป็น batch ตัวเลขที่อนุมัติแล้ว **โดยไม่เปลี่ยนรูปแบบ response**

## 6. บันทึกไว้ในรีจิสทรี

เพิ่ม 10 รายการ (5 DLD + 5 DOF) ใน `config/resource_licenses.json` ทุกรายการเป็น `pending` /
`project_publication_approved: false` / `commercial_use_confirmed: false` พร้อม `evidence` ที่มี
sha256 จริงจากการดึงข้อมูลวันที่ 2026-10-25 และ `unresolved` ที่เจาะจงปัญหาของแต่ละชุด

## 7. งานที่ยังค้าง / คำสั่งรับต่อ

1. **ปิดสิทธิ์กับผู้ดูแล DLD/DOF** — ขอชัดเจนว่า Open Data Common รุ่นใด และยืนยันว่าเผยแพร่ซ้ำได้
   พร้อมข้อความกำกับแหล่งที่ต้องใส่ (`attribution_text`)
2. **ยืนยันความหมายของคอลัมน์ `year`** ของ DLD (ปีปฏิทิน vs ปีรอบการผลิตสัตว์เลี้ยง) และของ DOF
3. **เติมช่องว่าง ไก่เนื้อ / ไก่ไข่** — ถาม DLD ว่ามีข้อมูลแยกนอก CKAN หรือไม่ (อย่า derive เอง)
4. **เติมช่องว่าง `ภาค` ของชุดสัตว์น้ำจืด/ปลาน้ำกร่อย** — ถาม DOF ว่ามีรุ่นที่มีคอลัมน์ภาคหรือไม่
   ปัจจุบันใช้ crosswalk มาตรฐาน 5 ภาค (ต้องติดป้ายว่าเป็นค่าที่ derive)
5. **สร้าง numeric batch** เมื่อสิทธิ์ผ่าน แล้วสลับ `LIVESTOCK_SAMPLE_MODE` เป็น `false`
   โดยคง response shape เดิม
6. **เพิ่มเมนู `/livestock` ใน `web/components/shell.tsx`** — ไฟล์นี้เป็นของ lane อื่น แดชบอร์ดใช้
   `active="explore"` ไปก่อนตาม precedent ของ `/crops` และ `/soil`
