## 2. ลำดับงานและกรอบเวลาการพัฒนา (Ingestion Execution Plan)

อัปเดต acquisition audit 23 ต.ค. 2569: CSV ที่ catalog ระบุใน datasets สาธารณะมี raw ครบ 58/58 resources (รวม RAR ที่ mislabeled CSV) และมี capture 33/33 datasets พร้อม selected native GIS อีก 2 resources ตรวจ hashes รวม 60 resources แล้ว ดู [ขอบเขตและ requirement matrix](doae-acquisition-audit.md) Non-CSV 24 resources ยังไม่เลือก, Database 6 ไม่อ่านข้อมูลบุคคล และการเชื่อมโมเดลตามรายการด้านล่างยังคงเป็นงานค้าง

### ระยะที่ 1 (P0): ข้อมูลหลักเพื่อการวิเคราะห์และโมเดลสถานการณ์ (Sprint 1)

อัปเดต 23 ต.ค. 2569: capture/staging CSV P0 ครบ **21 resources จาก 10 datasets, 1,943,298 source rows** แล้ว ดู [ผลและคำสั่งตรวจ](doae-p0-ingestion.md) งานเชื่อมโมเดล/หน่วย/พื้นที่/สิทธิ์ในรายการด้านล่างยังค้าง รต.01-02 เป็นแถว `(mock)` จึงยังไม่มี observation พืชจริงจาก resource นั้น การมีรายการใน catalog ไม่ยืนยันว่ามีข้อมูลพร้อมใช้

1. **พัฒนาตัวดึงและ Staging แผนการเพาะปลูกพืชฤดูแล้ง (`plan_dryplant`):**
   - ดึงครบ CSV 10 ไฟล์: รายตำบล 9 ไฟล์ปี 2561–2569 และสรุปปี 2568 อีก 1 ไฟล์ รวม 1,857,553 แถว; RDF เป็น metadata แยก
   - ใช้ `src/tadih/doae.py` และบัญชี schema/resource ที่ตรวจจริงใน `config/doae_p0_resources.json`; คำสั่งเดิมปี 2569 ยังใช้งานได้ ดู [หลักฐานและขอบเขต](plan-dryplant.md)
   - CSV ไม่ใช่ schema เดียวกันทั้งหมด: ไฟล์สรุปปี 2568 มี 597 แถว ประเทศ/ภาค/จังหวัดและ subtotal จึง staging แยกจากรายตำบล
   - ตรวจสอบโครงสร้างคอลัมน์ เปรียบเทียบแผนข้ามปีโดยไม่แปลงค่าว่างเป็น 0
2. **พัฒนาตัวดึงและ Staging ข้อมูลภาวะการผลิต รต.01-04 (`production-rt01-04`):**
   - ดึงครบ CSV 3 ไฟล์ (พืช รต.01-02 mock 1 แถวกักกัน, แมลง รต.03 78,762 แถว, นาเกลือ รต.04 450 แถวกักกันพื้นที่ติดลบ 1 แถว); repeated identities แมลง 48 / เกลือ 96 ยังไม่รวมยอด
   - เชื่อมโยงรหัสตำบลกับ DOPA Crosswalk ที่มีอยู่เดิม
3. **พัฒนาตัวดึงพื้นที่เสี่ยงภัยแล้งและน้ำท่วม:**
   - เชื่อมโยง `water-shortage-risk-area` (พื้นที่เฝ้าระวังขาดแคลนน้ำ) เข้ากับโมเดล Risk Signal Water
   - เชื่อมโยง `disaster_inthearea` และ `disaster_outsidethearea`
4. **พัฒนาตัวดึงแผนและผลการเพาะปลูกพืชฤดูฝน (`rainy-season-crop-plan`, `rainy-season-crop-result`):**
   - คำนวณอัตราความสำเร็จของการเพาะปลูก (Actual vs Plan) รายจังหวัด/ตำบล

### ระยะที่ 2 (P1): เสริมมิติเชิงพื้นที่ แผนที่ GIS และเศรษฐกิจฐานราก (Sprint 2)

อัปเดต 23 ต.ค. 2569: ดึงและ staging native P1 21 resources (19 CSV + JSON-LD สำนักงาน + GeoJSON จังหวัด) จาก 12 datasets ครบ 202,747 source records; 524 แถวออนไลน์ปี 2568 กักไว้เพราะค่ากับหัวคอลัมน์คลาดกัน นอกจากนี้คลาย/stage RAR วิสาหกิจปี 2566/2567 แล้ว ดู [ผลและข้อจำกัด](doae-p1-archives.md) งานวิเคราะห์/เชื่อมโมเดลตามรายการต่อไปยังต้องตรวจหน่วย/ช่วงเวลา/พื้นที่/สิทธิ์ก่อน

1. **นำเข้าพิกัดสำนักงานเกษตรจังหวัด (`doae-office-location`):**
   - ดาวน์โหลด JSON-LD และ stage สำนักงาน 955 รายการ พร้อมประเภทสำนักงาน พิกัด missing 1 รายการ ไม่เดาตำแหน่งหรือถือว่าทุกแถวเป็นจังหวัด
   - แปลง KML/GeoJSON เป็น Dimension ตารางที่ตั้งหน่วยงานในระบบ Power BI
2. **นำเข้าข้อมูลครัวเรือนและพื้นที่ประสบภัยเชิงพื้นที่ (`agricultural-households-disaster-affected-area-province`):**
   - บูรณาการเข้ากับ Shapefile แผนที่ 77 จังหวัด
3. **นำเข้าสถิติวิสาหกิจชุมชน (`smce-province`, `smce`, `doae_14_02`):**
   - วิเคราะห์ความเข้มแข็งของกลุ่มเกษตรกรและสินค้าเด่นรายจังหวัด
4. **นำเข้ามูลค่าสินค้าเฉพาะทาง:** สมุนไพร เครื่องเทศ และแมลงเศรษฐกิจ

### ระยะที่ 3 (P2): ความร่วมมือระดับระบบและการคุ้มครองข้อมูลส่วนบุคคล (Sprint 3)
1. **ประสานงานระบบทะเบียนเกษตรกร (`farmer.doae.go.th`):**
   - ร่างเอกสาร Data Contract เพื่อขอรับสถิติสรุปยอดรวม (Provincial/District Aggregates) โดยไม่แตะต้องข้อมูลส่วนบุคคลตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
   - จัดทำ [ร่าง Data Contract](doae-aggregate-data-contract-draft.md) แล้ว ยังไม่ส่งหรือเชื่อมฐานข้อมูลรายบุคคล และยังไม่ได้รับรอง/อนุมัติจากเจ้าของข้อมูล
2. **ตรวจสอบไฟล์บีบอัด `.rar` ของพืชอายุสั้น/พืชยืนต้นปี 2567:**
   - ทดสอบคลายไฟล์ในสภาพแวดล้อมควบคุม (Quarantine Extraction) เพื่อนำเข้า Staging ต่อไป
   - ดาวน์โหลด ตรวจ magic/hash คลายผ่าน stdout แบบจำกัดขนาด/เวลา และ staging ทั้งสองไฟล์แล้ว 647,756 source records; กักตัวเลขในวงเล็บ 173 แถว หน่วย/นิยาม native English fields และ repeated identities ยังรอตรวจ ไม่รวมเข้า warehouse
3. **P2 public sources เพิ่มเติม:** คำขอเพิ่มสินค้า 1,534 แถวและ RAR รายชื่อ/ที่ตั้งวิสาหกิจ 4 ไฟล์ รวม 304,480 แถว stage แล้ว เก็บชื่อ/รหัส/ติดต่อ/free text ภายใน ไม่ใช้เป็น observations หรือประกาศอนุมัติ Reference CSV 7 ชุดเก็บ raw แบบ positional เท่านั้น ไม่มีการอ่านข้อมูลจากฐานทะเบียนรายบุคคล

## 3. หลักเกณฑ์ธรรมาภิบาลข้อมูลที่ต้องปฏิบัติตามอย่างเคร่งครัด (Governance Rules)

1. **บันทึกหลักฐานข้อมูลดิบ (Raw Snapshots):** ทุกไฟล์ที่ดาวน์โหลดจาก CKAN ต้องคำนวณ SHA-256 และเก็บ Manifest ระบุ URL, วันเวลาที่ดึง และขนาดไฟล์ก่อนประมวลผลเสมอ
2. **รักษาระดับความละเอียดเดิม (Native Grain):**
   - ข้อมูลรายตำบล ห้ามนำไปสรุปเป็นยอดจังหวัดโดยพลการหากยังมีตำบลไม่ครบ
   - ข้อมูลรายแปลงหรือรายจุด ห้ามกระจายหรืออนุมานเข้าสู่ระดับพื้นที่อื่น
3. **รักษาค่าว่าง (Missing Values):**
   - ช่องว่าง, ขีด `"-"`, หรือข้อความว่าง ต้องถูกแปลงเป็น `null` เสมอ **ห้ามแทนที่ด้วย 0**
4. **การควบคุมสิทธิ์ (License Registry):**
   - ลงทะเบียนทุก Resource ใน [config/resource_licenses.json](file:///d:/code/thailand-agri-intelligence/config/resource_licenses.json) สถานะเริ่มต้นเป็น `pending`
   - ข้อมูลจริงทั้งหมดเก็บใน `data/local/` เท่านั้น ห้าม Commit เข้าสู่ Git สาธารณะเด็ดขาด
5. **การทดสอบอัตโนมัติ (Verification):**
   - ทุกโมดูลใหม่ต้องมี Unit Test ครอบคลุมการ parse, การรักษา null, การตรวจสอบ schema และการกักกันข้อมูลผิดปกติ
